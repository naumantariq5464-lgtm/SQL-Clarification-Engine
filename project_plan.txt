Text-to-SQL with Clarification Engine — Complete Project Plan
1. Project Objective

Build an AI-powered system that allows users to query a PostgreSQL database using natural language instead of writing SQL manually.

The system will:

Understand the user's question.
Detect ambiguity.
Ask for clarification when necessary.
Generate the correct SQL query.
Validate the SQL query.
Execute it on Neon PostgreSQL.
Convert the database result into a clear natural-language answer.

7. Natural Language Query

The user will ask questions like:

"How many customers do we have?"

"What were our total sales last month?"

"Which product sold the most?"

"Who is our best customer?"

"Which city has the highest number of customers?"

"Show me customers who spent more than $5,000."

"Which products generated the most revenue?"

"What was our average order value last month?"

8. Clarification Engine

This is the core feature of the project.

The system should not blindly guess when the user's question is ambiguous.

Example

User:

"Who is the best customer?"

The system detects ambiguity.

It could mean:

Highest total spending
Most orders
Highest average order value

So the AI asks:

"What do you mean by best customer: highest total spending, most orders, or highest average order value?"

User:

"Highest total spending."

Now the system generates the SQL.

9. LLM Structured Output

The LLM should return a structured response.

Example:

{
  "needs_clarification": true,
  "clarification_question": "Do you mean highest spending or most orders?",
  "sql": null
}

For a clear question:

{
  "needs_clarification": false,
  "clarification_question": null,
  "sql": "SELECT ..."
}

Pydantic will validate this output.

10. SQL Generation

After the user's intent is clear:

User Question
      ↓
LLM
      ↓
SQL Generation

Example:

User:

"Which customer spent the most money?"

Generated SQL:

SELECT
    c.id,
    c.name,
    SUM(o.total_amount) AS total_spent
FROM customers c
JOIN orders o
    ON c.id = o.customer_id
WHERE o.status = 'completed'
GROUP BY c.id, c.name
ORDER BY total_spent DESC
LIMIT 1;
11. SQL Validation & Safety

We should never blindly execute LLM-generated SQL.

The backend will validate the query first.

Initially, we will allow only:

SELECT

and reject dangerous operations such as:

INSERT
UPDATE
DELETE
DROP
ALTER
TRUNCATE

The system should also check:

Valid tables
Valid columns
SQL syntax
Query complexity
Unauthorized data access

13. Generate Final Answer

The raw database result will be converted into a human-readable response.

Instead of:

{
  "name": "Ali",
  "total_spent": 18450
}

The user receives:

Ali is the highest-spending customer with total purchases of $18,450.

14. Conversation / Clarification Flow

The system must maintain context during clarification.

Example:

User:
Who is the best customer?

AI:
Do you mean highest spending or most orders?

User:
Highest spending.

AI:
[Generates SQL based on the original question
 + user's clarification]

The clarification should not be treated as a completely new query.
